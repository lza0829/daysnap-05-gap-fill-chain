# 日镜账

中文名：**日镜账** · 前缀 `daysnap` · 端口 **6600 / 11600**

## 骨架

**日终余额抽取 → 周期快照落行 → 变动流水回放核对 → 断档/跳变检出 → 快照与回放差额清单**

皮：收单/结算账户的日终余额镜。去皮是 **周期快照事实 + 流水回放守恒 + 断档跳变检出**，不是银行核心 CRUD、不是日结封账锁定、不是双边齐账。

## 断档口径（关键设计取舍，全局只贯彻一种）

选定 **口径 A · 同票补齐链**：非开户首日缺前日有效镜时，抽取事务在同一个
`BEGIN IMMEDIATE` 事务内，从最近有效锚点（或开户日前夜的虚拟零锚
`开户零`）沿营业日逐日物化整条缺失链（`来源=同票补齐`），再写当日有效镜。
当日镜存在，且 `开端来源` 为 `同票补齐` / `前日快照` / `开户零`；
**绝不**在跨断档时以零开端落正式有效镜（毒源标记 `以零为开端` 全库不允许出现）。

**显式桥接（口径 B 的凭证化处置，作为操作员主动旁置保留，不是默认路径）**：
对「账户 × 目标日」立 `断档桥接凭证` 后，该日抽取整拒（HTTP 409）、无当日有效镜，
直至解除。桥接与当日有效镜数据库事务级互斥（局部唯一索引保证一户一日至多一张有效桥）：

- 已有当日有效镜再立桥 → 409 `状态冲突`；
- 抽取时（含同票补齐链途经的任一缺口日/锚点日）复检到有效桥 → 整票回滚 409，
  链上不留任何半截镜；
- 并发「立桥 vs 抽取」由 `BEGIN IMMEDIATE` 串行化 + 锁内复检，
  结果只可能是 `200/409` 或 `409/200`，永不 `200/200` 并存。

因此两种架构下「首次失败/阻退后当日有效快照行是否存在」确定可区分：
同票补齐成功 → **有**当日有效镜（且中间日镜也在）；桥接阻退 → **无**当日有效镜
（整票回滚，连非有效半截行都没有）。

### 断档处置只读接口

`GET /api/断档处置?账户键=&营业日=`（也支持 `/api/断档处置/{acct}/{day}`、
`/api/断档状态`、`/api/gap-disposition`；查询参数兼容 `account/date/day`）。
同时给账户与日期返回单对象，核心字段：

| 字段 | 含义 |
| --- | --- |
| `缺日` | 从前一日回溯到最近有效锚点之间缺失的营业日（升序） |
| `处置` | `无断档` / `已补齐` / `待补齐` / `待抽取` / `桥接阻断` / `未到开户日` |
| `当日可否抽`（=`canExtract`） | 桥接阻断时为 false，其余可抽（缺日会同票补齐） |
| `valid`（=`有效`） | 当日有有效镜、缺日链已闭合且无阻断才 true |
| `当日有效镜` / `当日余额` / `开端来源` | 当日行有无及其 provenance |
| `桥接凭证号` / `阻断桥接营业日` / `桥接横断链` | 阻断凭证；桥在补齐链中间日时给出实际阻断日 |

只给 `营业日` 返回逐账户视图数组；都不给返回案件 + 桥接工作台。

写接口：`POST /api/断档补齐`（同票补齐并抽取）、
`POST /api/断档桥接`（别名 `/桥接`、`/断档旁置`）、
`POST /api/断档桥接/解除`（别名 `/断档桥接解除`、`/桥接解除`，可用 `凭证号` 或
`账户键+营业日`；断档页对横断桥按 `阻断桥接营业日/凭证号` 解除）、
`POST /api/断档处置`（按 `动作/action/处置` 分派）、`GET /api/断档桥接?状态=`。

| 对象 | 作用 |
| --- | --- |

| 断档/跳变 | 缺前日镜、偏离阈值 |
| 旁置簿 | 未入账载荷 |
